# SKILL.md 结构模板（skill-structure-template）

创建技能时按此骨架组织。核心原则：描述 = 何时使用（仅触发条件），正文按渐进式披露组织，庞杂内容移至 references/。

## 前置元数据（YAML）

```yaml
---
name: Skill-Name-With-Hyphens
description: 当 [特定触发条件和症状] 时使用
---
```

- 名称：仅由字母、数字和连字符组成。使用主动语态，动词优先（`creating-skills` 而非 `skill-creation`）。
- 用户约定（2026-08-04）：frontmatter 中的 `name` 与目录名一律使用大驼峰（如 `CreatePrompts/`、`ReviewPr/`），两处保持一致。
- 描述 等于 何时使用，而非技能做什么。描述应该只描述触发条件。不要总结技能的流程或工作流——测试表明智能体会走捷径，只读描述而不读完整技能。
- 使用第三人称（注入到系统提示中）。
- 总长度最多 1024 字符；如有可能保持低于 500。

## 正文结构（推荐）

```markdown
## 概述
1-2 句话说明核心原则。

## 何时使用
使用场景和症状。何时不使用。

## 核心流程
编号的阶段，对非显而易见决策使用流程图。

## 快速参考
表格或要点，用于扫描常见操作。

## 常见错误 / 合理化借口
什么问题 + 如何修复。

## 红旗信号
停止信号。
```

渐进式披露：SKILL.md 最好在 500 行以内。对于更庞大的内容，移至参考文件：

```
skill-name/
├── SKILL.md（工作流 + 指针）
└── references/
    ├── topic-a.md
    └── topic-b.md
```
