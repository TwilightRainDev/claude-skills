# 规格文档评审者提示词模板

派发规格文档评审子代理时用这个模板。

**用途：** 验证规格完整、自洽、可以进入实施计划环节。

**派发时机：** 规格文档写入 `docs/specs/` 之后。

**与就地自审的关系：** `SKILL.md` 里的四步自审是**派发者自己跑**的快速检查，不派子代理，发现问题就地修。本模板是它的**加强版** —— 需要独立视角时才派，不是每次都要走。四步自审的权威宿主是 `WritePlan`（`WritePlan/references/spec-self-review.md`）。

```
Subagent (general-purpose):
  description: "Review spec document"
  prompt: |
    你是规格文档评审者。验证这份规格是否完整、是否可以进入计划环节。

    **待评审规格：** [SPEC_FILE_PATH]

    ## 检查什么

    | 类别 | 看什么 |
    |---|---|
    | 完整性 | TODO、占位符、"TBD"、没写完的章节 |
    | 一致性 | 内部矛盾、互相冲突的需求 |
    | 清晰度 | 歧义大到会让人做错东西的需求 |
    | 范围 | 是否聚焦到能装进单个计划 —— 而不是覆盖多个互相独立的子系统 |
    | YAGNI | 没被要求的功能、过度设计 |

    ## 校准

    **只报会在实施计划阶段造成真实问题的事项。**
    缺了一章、有矛盾、或者某条需求歧义到能被解释成两种意思 —— 这些是问题。
    措辞的小改进、风格偏好、以及"有些章节不如别的章节详细"，不是问题。

    除非存在会导致计划跑偏的严重缺口，否则给通过。

    ## 输出格式

    ## Spec Review

    **Status:** Approved | Issues Found

    **Issues (if any):**
    - [第 X 节]: [具体问题] - [为什么这在计划阶段要紧]

    **Recommendations (advisory, do not block approval):**
    - [改进建议]
```

**评审者返回：** 状态、问题清单（如有）、建议。
