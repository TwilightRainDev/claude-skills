# Apple 设计语言（判断力层）

这一层回答"为什么这样做"，`motion.md` 与两个 mode 文件回答"具体用什么值"。两者冲突时以本文件的原则为准。

来源：Apple WWDC 设计演讲体系（*Designing Fluid Interfaces* 2018、*The Details of UI Typography* 2020、*Principles of Great Design*）在 Web 平台上的落地。

## 核心命题

> 当界面与人的思考方式和运动方式对齐时，它就不再像一台计算机，而像人的延伸。

界面"活"的条件：**运动从当前屏幕上的值开始、继承用户的速度、向前投影动量、并且随时能被抓住反转。** 弹簧之所以是主力工具，正因为它天然可中断、天然带速度。

Apple 把设计拆成服务四种人类需求：**安全/可预期、理解、成就、愉悦**。下面每一条规则都服务其中之一。

## 1. 响应 —— 消灭延迟

延迟一出现，"直接感"就断崖式下跌。

- **在 pointer-down 响应，不是 release。** 按钮按下瞬间就给高亮。等 `click` / touch-up 才反馈，手感是死的。
- **对每一处延迟保持警惕。** 审查 debounce、人为定时器、过渡等待、约 300ms 的点击延迟。输入路径上任何非必要的环节都是退化。
- **反馈要在交互过程中持续，而不只在结束时。** 拖拽、滑块、抽屉必须全程与指针 1:1，绝不能只在手势结束时才动一下。

```css
.button:active {
  transform: scale(0.97);
  transition: transform 100ms ease-out;
}
```

## 2. 直接操纵 —— 1:1 跟手

> 触摸和内容应该一起移动。

拖动时元素必须粘在手指上，并且**尊重抓取时的偏移** —— 抓住瞬间把元素中心对齐光标，幻觉立刻破灭。

- 用 Pointer Events + `setPointerCapture`，指针离开元素边界后仍继续跟踪。
- 维护一小段**速度/位置历史**（最近几次 `pointermove`），不要只存当前点 —— 释放时要用速度。

```js
el.addEventListener('pointerdown', (e) => {
  el.setPointerCapture(e.pointerId);
  const grabOffset = e.clientY - el.getBoundingClientRect().top; // 尊重抓取位置
});
```

## 3. 可中断性 —— 最重要的单条原则

> 想法和手势是并行发生的。

任何动画都必须能在任意时刻被中断和改向。用户必须能抓住飞行中的元素反转它，而不是等动画跑完。一个正在关闭、又被用户抓住的模态框，应该跟手，而不是先关完再重开。

- **过渡期间绝不锁死输入。**
- **永远从当前表现值开始动画，而不是目标值。** 中断时读取元素实时的屏幕 transform 作为起点；从逻辑值/目标值起步会产生可见跳变。
- **手势驱动的动效避免用 CSS transition 和 `@keyframes`** —— 它们无法被平滑抓住并反转。弹簧默认就从当前值出发，正好是可中断性需要的。
- **手势反向时混合速度，不要硬切。** 在反向点用一个动画替换另一个会产生速度断点，像撞墙。选能在重定向时携带速度的弹簧库（iOS 原生的 *additive animations* 做的是这件事）。
- **二维运动拆成独立的 X、Y 弹簧。** 对二维距离用单个弹簧，在 X/Y 速度不同时会失步。

## 4. 行为优先于动画 —— 用弹簧

> 把动画想成你和对象之间的对话，而不是界面预设好的东西。

预设好的固定时长动画无法响应新输入；弹簧可以 —— 新输入只是改变目标值，运动保持连续。**凡是用户能碰到的东西，都优先弹簧。**

Apple 刻意把物理三参数（mass/stiffness/damping）替换成两个设计师友好的参数：

- **Damping（阻尼比）** —— 控制过冲。`1.0` = 临界阻尼，无回弹，平滑落定。`< 1.0` = 过冲振荡，越低越弹。
- **Response（响应时间）** —— 值到达目标的速度，单位秒。越低越干脆。**它不是 duration** —— 弹簧没有固定时长，落定时间是从参数里涌现的。

**默认值：**
- 大多数 UI 从 **damping `1.0`**（临界阻尼）起步 —— 优雅、不分散注意力。
- **只在手势本身携带动量时**才加回弹（**damping ~`0.8`**）：甩、抛、拖拽释放。一个淡入的菜单回弹是错的；一张被甩出去的卡片回弹是对的。

**Apple 实际出厂的参数：**

| 交互 | Damping | Response |
|---|---|---|
| 移动 / 重定位（如 PiP） | `1.0` | `0.4` |
| 旋转 | `0.8` | `0.4` |
| 抽屉 / Sheet | `0.8` | `0.3` |

Web 映射（Motion / Framer Motion）：`bounce` + `duration` 的弹簧 API 与 Apple 的 damping + response 对应良好。安全的内务风格是**默认处处 damping 1.0**，回弹留给有动量驱动的物理交互。

```js
import { animate } from 'motion';

animate(el, { y: 0 }, { type: 'spring', bounce: 0, duration: 0.4 });    // 临界阻尼默认
animate(el, { y: t }, { type: 'spring', bounce: 0.2, duration: 0.4 });  // 有甩动前置，才允许回弹
```

## 5. 速度交接 —— 拖拽与动画之间的接缝

手势结束时，动画必须**以手指的确切速度继续**，这样拖拽和动画之间没有可见接缝。这一处细节最能区分"流畅"和"还行"。

把指针释放速度作为弹簧的初速度传入。部分弹簧 API 要的是**相对速度**，用剩余距离归一化：

```
relativeVelocity = gestureVelocity / (targetValue − currentValue)
```

例：元素在 `y=50`，目标 `y=150`（还差 100px），手指速度 50px/s → 弹簧初速度 `50 / 100 = 0.5`。Framer Motion / Motion 的 `velocity` 选项吃绝对值 px/s，通常直接传原始值。

## 6. 动量投射 —— 动画的终点应该是手势"要去的地方"

> 小输入，大输出。

不要从**释放点**吸附到最近边界。用速度**投影出静止位置**（和滚动减速完全一样），再吸附到离投影点最近的落点。这是"甩出去"手感的来源。

Apple 的精确投射函数：

```js
// decelerationRate ≈ 0.998 为常规滚动手感；0.99 更干脆
function project(initialVelocity /* px/s */, decelerationRate = 0.998) {
  return (initialVelocity / 1000) * decelerationRate / (1 - decelerationRate);
}

const projectedEndpoint = currentPosition + project(releaseVelocity);
const target = nearestSnapPoint(projectedEndpoint);      // 用投影点选目标
animateSpringTo(target, { velocity: releaseVelocity });  // 再交接速度（第 5 节）
```

注意：物理教科书里的 `v²/(2·decel)` **不是** Apple 出厂的形式，用上面的指数衰减式。好的 bottom-sheet 和轮播（Vaul、Embla）就是这么做的。

## 7. 空间一致性 —— 对称路径、锚定原点

> 如果某样东西以一种方式消失，我们期待它从来的地方出现。

- **进和出走同一条路径。** 从右侧滑入的面板必须向右消失。右进底出会让人困惑、觉得断裂。
- **把交互锚定到它的来源。** 菜单、popover、sheet 应该从触发它的元素长出来 —— 设 `transform-origin` 到触发器，让按钮与内容的方位关系显而易见。
- **可逆过渡镜像缓动曲线**，让去程和回程匹配（两个方向用互逆的贝塞尔控制点）。

## 8. 沿手势方向给出暗示

人从轨迹预测终态。中间帧应该预告去向 —— 控制中心模块"朝手指方向上浮展开"。让中间帧指向结果，而不是盲目插值。

## 9. 橡皮筋 —— 软边界

到达边界时渐进抵抗，而不是硬停。硬停读作"冻住了"；持续抵抗读作"有响应，但这里没有更多了"。越界的阻尼随距离递增。

```js
function rubberband(overshoot, dimension, constant = 0.55) {
  return (overshoot * dimension * constant) / (dimension + constant * Math.abs(overshoot));
}
```

## 10. 手势设计细节（"手感"清单）

- **点按：** touch-**down** 即高亮，touch-**up** 才提交。目标周围留约 10px 的宽容/命中扩展，允许拖开再拖回取消。
- **拖拽/滑动：** 先用一个小阈值（约 10px 的 hysteresis）确认方向，然后 1:1 跟踪。
- **从第一次移动起并行识别所有可能的手势**，意图明确后再果断取消落选者。避免只报告**终态**的识别器（`swipeleft` 类事件），它们丢掉了连续跟踪所需的中间态。
- **尽量减少消歧延迟。** 双击检测不可避免地拖慢单击，只在真正存在双击的地方付这个代价。

## 11. 帧级平滑

平滑取决于**帧里有什么**，不只是帧率。

- 每帧位移保持在感知阈值以下，避免频闪。
- 高速运动时，轻微的**运动模糊 / 拉伸**能编码速度，比一条锐利的硬边更好读。
- `requestAnimationFrame` 是 Web 的显示同步时钟（Apple 用 `CADisplayLink`）。只动合成器友好的属性 —— `transform` 和 `opacity` —— 在运动临近时用 `will-change` 提示。

## 12. 材质与层次 —— 半透明传达层级

Apple 把半透明材质当作漂浮的功能层：带来结构，但不抢焦点。Web 上用 `backdrop-filter` 近似。

- **导航栏/工具栏/sheet 建成半透明层**（`backdrop-filter: blur()` + 半透明背景），内容在其下滚动 —— 而不是占据固定条带的实色条。
- **材质重量编码层级：** 更重/更深的材质分隔结构区域（侧边栏）；更轻的材质把注意力引向可交互元素（按钮）。**绝不要把浅色半透明面叠在另一个上面** —— 可读性会崩。
- **更大的表面应该显得更厚：** 比小 chip 更强的模糊 + 更深的阴影。考虑场景感知的阴影 —— 压在花哨/文字内容上更重，压在纯色背景上更轻。
- **要专注就压暗，要保持流就分离。** 模态任务用遮罩压暗并推远背景；并行的非阻塞面板只用半透明和位移、**不加遮罩**，不打断心流。层叠 sheet 逐级压暗并推远父层。
- **Vibrancy 让文字在变化的背景上仍然可读。** 在半透明面上不要用平灰文字 —— 用更高对比、略重的字重，并小幅增加字距。颜色放在实色层上，不要放在半透明前景上。
- **用滚动边缘效果代替硬分隔线。** 别用 1px 边框压住粘性头部，在内容与悬浮 chrome 相接处渐隐一小段模糊/渐变遮罩 —— 且只在悬浮 UI 真正覆盖内容的地方。
- **物化，而不只是淡入。** 玻璃/模糊表面进出时，模糊半径和缩放一起动，让表面读起来像真实材质到来，而不是一次普通的透明度渐变。

```css
.toolbar {
  background: rgba(255, 255, 255, 0.6);
  backdrop-filter: blur(20px) saturate(180%);
  border-top: 1px solid rgba(255, 255, 255, 0.4); /* 顶部亮边 = 光打在材质上 */
}
```

## 13. 多模态反馈 —— 动效 + 声音 + 触觉

来自 *Designing Audio-Haptic Experiences* 的三条规则：

1. **因果性** —— 必须明显看出是什么触发了反馈。在真正的因果事件上触发（开关翻转、元素吸附归位），并让反馈的性格匹配动作的物理性。
2. **和谐性** —— 视觉、声音、触觉必须**在同一帧**发出。它们之间的延迟会摧毁幻觉。不要让 CSS transition 拖慢音频/触觉（Vibration API）。
3. **效用性** —— 只在配得上的地方加反馈。把触觉/声音留给有意义的时刻（成功、错误、提交、吸附）。过度反馈会训练用户忽略全部反馈。

## 14. 减少动态效果与无障碍

"减少动态"不等于"没有反馈"，而是**更温和、不引发前庭不适的等价物**。三个独立信号都要响应，并内建进组件：

- **`prefers-reduced-motion: reduce`** —— 把滑动/弹簧/视差换成短促的**透明度交叉淡入**或静态过渡。去掉弹性/过冲。保留有助于理解的透明度与颜色变化。
- **`prefers-reduced-transparency: reduce`** —— 让半透明表面更磨砂/更实：提高背景不透明度，去掉模糊。
- **`prefers-contrast: more`** —— 接近实色的背景加一条明确的对比边框。

另：避免全视口运动的背景、缓慢的循环振荡（接近 0.2 Hz / 5 秒一周期）、以及亮度突变（深色浅色主题切换要缓动）。大幅移动的物体在移动中做半透明，大幅面重定位时先淡出、落定后再淡入。

```css
@media (prefers-reduced-motion: reduce) {
  .sheet { transition: opacity 200ms ease; transform: none !important; }
}
@media (prefers-reduced-transparency: reduce) {
  .toolbar { background: white; backdrop-filter: none; }
}
```

## 15. 排版 —— 光学尺寸、字距、行高

Apple 让字形随尺寸改变形态，Web 上遵循同样的纪律。

- **字距（letter-spacing）是尺寸专属的 —— 绝不用一个值应付所有尺寸。** 大号显示文字要**负**字距（字越大，默认间距读起来越散）；小号文字要略**正**字距以保可读。固定的 `letter-spacing` 一定在某处是错的。标题收紧，正文接近 `0`。
- **行高与尺寸反向。** 大标题紧，正文松。有高升部/降部的文字体调大，信息密集的 UI 调小。
- **层级由字重 + 字号 + 行高成套构成**，不是只靠字号。用字重强调 —— 它在不占更多空间的前提下增加存在感。
- **尊重用户的文字大小设置**（Dynamic Type）。布局要**跟着**文字缩放 —— 间距用 `rem`/`em` 而非固定 px，字号变大了布局不会崩。
- **优先用平台系统字体**，再用自定义字面；它自带光学尺寸、字距表和可读性调校。有理由才覆盖。

```css
:root { font: 100%/1.5 system-ui, sans-serif; }

.display {
  font-size: clamp(2rem, 5vw, 4rem);
  line-height: 1.05;        /* 大字紧行高 */
  letter-spacing: -0.02em;  /* 随尺寸增长而收紧 */
  font-optical-sizing: auto;
}
```

## 16. 设计基础 —— 八项原则

用这八项作为推理时的命名：

1. **Purpose（目的）** —— 有意图地做，决定**不**做什么。每个功能都在索取用户的时间、注意力和信任；只在该有回报的地方花这笔预算。
2. **Agency（自主）** —— 让人保持控制：给选择，不强迫单一路径。用宽容兜底 —— 失误容易撤销；只有真正破坏性、不可逆的操作才用确认对话框（克制使用，滥用会训练用户无脑点过）。
3. **Responsibility（责任）** —— 以用户利益行事。隐私：在对的时机询问、只问所需、透明。安全：预判误用与伤害 —— 尤其涉及 AI 时。加预览、确认、免责声明；砍掉风险大于价值的功能。
4. **Familiarity（熟悉）** —— 建立在人们已知的事物上。用既不过于直白也不过于抽象的隐喻（垃圾桶意味着删除），并尊重其物理性。保持一致：看起来一样的东西必须行为一样、待在同一个位置，人才可预测接下来发生什么。只有在能证明更好时才打破熟悉模式 —— 而且要测，不要假设。
5. **Flexibility（灵活）** —— 为不同情境、设备和完整的能力谱系设计。适应平台（iPhone = 快速触摸；桌面 = 精确指针的深度工作流）与情境。包容性设计（年龄、语言、专业度、无障碍）。当没有单一布局适合所有人时，让人自己调整 —— 重排控件、隐藏不用的东西。
6. **Simplicity（简洁，不是极简）** —— 剥掉非必要，让核心目的发光；把所有东西埋在一处看起来极简但并不简洁。要精炼（平实语言、无术语、更少步骤）且清晰（用层级 —— 顺序、间距、对比 —— 让最重要的最明显）。每个元素都要挣得自己的位置；有时**增加**上下文反而简化。常见路径优先展示，高级选项下沉一级。
7. **Craft（工艺）** —— 不妥协的细节带来信任。漂亮的排版、适配明暗的颜色、清晰的图标、即时自然的响应动画。没有什么是随机的 —— 每个间距、时间和对齐值都是你能辩护的有意选择。抖动滚动、图标错位、旋转变形读作粗心。
8. **Delight（愉悦）** —— 是前七项做对的结果，不是撒在上面的彩带。决定你想让人感受到的情绪（平静、自信、兴奋），并在每个决策里强化它。

服务于上述原则的战术规则：

- **反馈有四种：** 状态、完成、警告、错误。确认有意义的操作，暴露进行中的状态，在问题发生前警告，**内联**校验（不是提交时才校验）。
- **寻路。** 每个屏幕都应回答：我在哪？我能去哪？那里有什么？我怎么出去？绝不困住用户。
- **分组与映射。** 邻近暗示关系；把控件放在它影响的事物旁，并让控件排布镜像它所改变的东西。如果需要标签来解释一个控件，映射就是弱的。
- **直接、具体的标签胜过安全的泛称。** 导航项按内容命名（"进度""资料库"），而不是模糊的伞形词（"首页"）。具体带来可预测。

## 17. 流程

- **交互式地做原型 —— 一个可交互 demo 抵得上"一百万张静态稿"。** 界面是在造和玩的过程中被发现的；能跑的原型还会立下具体门槛，防止最终实现平庸。
- **交互和视觉一起设计。** "你不应该能分辨出哪里结束、哪里开始。"动效不是像素之后再加的一层。
- **用真实的人、在真实情境中测试**；用新鲜的眼光审查动效 —— 慢放或逐帧播放，才能看见全速下不可见的东西。
