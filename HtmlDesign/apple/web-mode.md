# mode: web —— apple.com 官网视觉

**适用**：网页、落地页、产品页、营销页、品牌站、活动页。
**不适用**：仿 App 界面 —— 那走 `platform-mode.md`。

这套语言的内核是**产品摄影 + 近乎隐形的 UI**：页面是一叠通版"瓦片"，底色在明暗之间轮换，**没有东西与产品争夺注意力**。

内核没变，但**编排变了**。2015 年前后，每个瓦片都是同一个模子：居中标题 → 一行副标 → 两枚蓝色药丸 → 一张居中大图。现在那只是四种编排之一，而且是使用频率最低的一种。一页里连做三次同样的"居中堆叠"，无论字号调多大都还是那个年代的观感 —— 详见下面「瓦片编排」。

## 颜色

### 强调色（只有一个）

| Token | 值 | 用途 |
|---|---|---|
| `--primary` | `#0066cc` | **唯一的品牌级交互色（Action Blue）**。所有文字链接、所有蓝色药丸 CTA、焦点环根色 |
| `--primary-focus` | `#0071e3` | 键盘焦点环专用（`outline: 2px solid`） |

| Token | 值 | 用途 |
|---|---|---|

### 渐变

**没有装饰性渐变。** 产品摄影（摄像头模组、表带反光、AirPods 倒影）里的空气感是影像固有的，不是 CSS 渐变叠加。Apple 是罕见的**零渐变 token** 的奢侈品牌站点。

- **Display**：`SF Pro Display, system-ui, -apple-system, sans-serif` —— 用于 ≥ 19px
- **Text/UI**：`SF Pro Text, system-ui, -apple-system, sans-serif` —— 用于 < 20px 的正文、说明、按钮、链接

> 旧阶与本阶的差别集中在三处：**显示尺寸整体上移**（瓦片标题 40 → 56，主视觉 56 → 流式 40–96）、**显示级行高收紧**（`display-md` 从 1.47 收到 1.15）、**字距由死 px 改 em**。第一条决定页面是否还像 2015 年，第二条决定标题读起来是"立"的还是"散"的，第三条是前两条能成立的前提 —— 主视觉一旦流式，一个固定 px 的字距必然在某一端是错的。

### 排版原则（不可破）

- **字距用 em，不用 px。** 负字距是"Apple 紧"的韵律来源，但**大字的收紧量必须随字号缩放** —— 主视觉是流式的，一个写死的 px 值必然在小屏过紧、在大屏过松。显示级 `-0.012em` 到 `-0.022em`，正文近 `0`，眉标反过来给正字距（`0.06em`）。
- **正文 17px，不是 16px。** 打破 SaaS 惯例。这一像素给了页面"在读，不是在扫"的节奏。
- **显示尺寸要大。** 瓦片标题 56px、分节宣言 64px、主视觉流式到 96px。**这是本阶与 2015 年那版的根本差别** —— 当年的主视觉封顶 56px，在今天的屏幕上读起来像次级标题。
- **显示级行高要收。** 1.04–1.15。`display-md` 的旧值 1.47 是给多行分节标题留的松法，现在读起来是散的。
- **标题用 600 不用 700。** 700 仅在 `tagline` 需要更多断言时少量使用。
- **字重 300 只留给超大显示字**（≥64px）。它在正文尺寸上不是"空气感"，是虚弱。
- **行高是场景专属的。** 显示尺寸 1.04–1.15（紧），正文 1.5，页脚密集链接列反常地松（2.2，这是特性不是 bug）。
- **字重 500 被刻意剔除。** 阶梯是 300 / 400 / 600 / 700，中等强调一律用 600。
- **标题加 `text-wrap: balance`，正文加 `text-wrap: pretty`。** 中文标题极易在末行只掉一个字（"…听不见的地 / 方。"），手工插 `<br>` 换个宽度就崩。balance 交给浏览器均分。两者都是渐进增强。

### 非 Apple 平台的替代字体

SF Pro 是 Apple 专有字体。离开 Apple 设备时：

- 字体栈首位始终放 `system-ui, -apple-system, BlinkMacSystemFont` —— 在 macOS/iOS/Safari 上解析为真实 SF Pro。
- 非 Apple 平台用 **Inter**（Google Fonts 可变字体）最接近。Inter 600 + `font-feature-settings: "ss03"` 近似 SF Pro 的圆润 "a"。
- 显示尺寸额外压 `-0.01em` 字距 —— Inter 默认字距比 SF Pro 略宽。
- 正文行高收紧 `0.03`（1.47 → 1.44）—— Inter 的 x-height 更高，需要的行距更少。

## 布局

### 间距

8px 基准；结构性布局吸附到 8/12/16/20/24，2/4/5/6/7 只用于紧密的排版微调。

`4px` · `8` · `12` · `17` · `24` · `32` · `48` · `64` · **`96`（section）** · **`120`（宣言 / 通版影像瓦片）**

- **瓦片内纵向内边距 96px**（宣言瓦片与通版影像瓦片 120px）；瓦片之间 **0 间隔**堆叠，颜色变化本身就是分隔。
- 工具栅格卡片内边距 24px。按钮内边距纵向 8–11px、横向 15–22px。
- **通用节奏常量**：17px 正文行高倍数（约 25px 行）与 21px 标语字号，在每个分析过的页面上都出现。

### 栅格与容器

- 左右留白用 `--gutter-page`（`clamp(24px, 5vw, 96px)`），**不要用 `--space-lg`（24px）**。1440 视口下 24px 的边距读起来是"内容顶到屏幕边"，那是旧的紧法；现在内容区两侧要留出可见的空气。全局导航是例外，它可以贴着 `24px`。
- 文字密集区最大内容宽度约 **980px**；产品栅格约 **1440px**；产品瓦片通版无限制。
- 工具卡栅格 3–5 列；主页偶发分区 2 列并排瓦片；产品瓦片主视觉单列居中堆叠。
- 工具栅格列间距 20–24px。

### 留白哲学

**Apple 的留白是产品的底座。** 每片瓦片标题上方至少 64px 空气，下方 48–64px。产品渲染图从不拥挤，最近的元素离产品图至少 40px。**页脚是唯一例外** —— 那里刻意加密，让完整信息架构一眼可见。

## 纵深

| 层级 | 处理 | 用途 |
|---|---|---|
| 平坦 | 无阴影无边框 | 通版瓦片、全局导航、页脚、正文区 |
| 柔发丝 | 1px `rgba(0,0,0,0.08)` | 工具卡、子导航磨砂分隔 |
| 背景模糊 | 米白 80% + `backdrop-filter: blur()` | 子导航、购买页悬浮吸底条 |
| 文字保护层 | `--scrim-top` / `--scrim-bottom` | **仅**当白字压在摄影上时。见下 |
| 产品阴影 | `rgba(0,0,0,0.22) 3px 5px 30px 0` | 搁在表面上的产品渲染图 |

> **关于 scrim。** "没有装饰性渐变"这条依然成立 —— 页面底色、按钮、卡片上不许出现渐变。但文字压在摄影上时，**必须**有一条渐变到透明的暗层，否则对比度完全取决于拍摄到的那块像素碰巧有多亮。这是功能件，不是装饰件。
>
> **锚在文字块上，不要锚在瓦片上。** 瓦片高度随视口变（`min-height: min(78vh, 760px)` 这类），文字块高度却是固定的。把渐变铺满瓦片，换个视口文字就跑出强区 —— 实测过：同一份 CSS，眉标从 1.16 掉到 2.94，两种都不过 AA。正确做法是给文字容器加一个向上溢出的伪元素：
>
> ```css
> .bleed__copy { position: relative; }
> .bleed__copy::before {
>   content: "";
>   position: absolute;
>   inset: -110% -100% 0 -100%;   /* 向上溢出一个文字块的高度 */
>   background: var(--scrim-bottom);
>   pointer-events: none;
> }
> ```
>
> 伪元素在子元素之前绘制，文字自然压在它上面，不需要 z-index。

**阴影哲学：整个系统只有一处投影，只给产品摄影图。** 绝不用于卡片、按钮、文字。UI 的层级来自 (a) 表面颜色变化（浅瓦片 ↔ 暗瓦片）与 (b) 粘性条上的背景模糊。那一处阴影是为了给产品重量感，不是为了 UI 层级。

## 形状

| Token | 值 | 用途 |
|---|---|---|
| `--rounded-none` | `0px` | 通版产品瓦片（不切角） |
| `--rounded-xs` | `5px` | 行内链接做成细 chip 时（罕见） |
| `--rounded-sm` | `8px` | 深色工具按钮（登录、购物袋）、行内卡片图 |
| `--rounded-md` | `11px` | 珍珠白按钮胶囊 |
| `--rounded-lg` | `18px` | 商店工具卡、配件栅格卡 |
| `--rounded-xl` | `28px` | bento 卡片、影像卡 —— 卡片化编排的现代半径 |
| `--rounded-pill` | `9999px` | 主蓝色药丸 CTA、子导航购买按钮、配置器 chip、搜索框 —— 标志性的 Apple 药丸 |
| `--rounded-full` | `9999px` / 50% | 压在照片上的圆形控件 chip |

**不要混用圆角语法** —— 紧凑工具用 `sm`、卡片用 `lg` 或 `xl`、药丸用 `pill`，中间不要加别的东西（珍珠白按钮的 `md` 是罕见例外）。

**通版瓦片永远是 `0`。** 它要贴到视口左右边缘，切角会在屏幕上露出两个圆角破绽。圆角只属于"浮在页面上的一张卡"。

### 图像几何

- 主视觉通版，主页 21:9 或更高，环境页与商店 16:9。
- 产品渲染图用带透明的 PNG/WebP，搁在表面瓦片上并承接系统阴影。
- 配件栅格 1:1 方裁，`lg`（18px）圆角，浅中性底，产品居中留 20–40px 内边距。
- **主视觉瓦片里的图像不切圆角** —— 通版矩形。圆角只出现在行内卡片图上。

## 影像 —— 这套语言的主角

**web 模式是摄影驱动的。** UI 退让不是修辞：整页的说服力几乎全部由影像承载。没有合适影像的 apple.com 风格页面，只剩一堆白底和一行蓝色药丸，是空的。**先解决影像，再排版式。**

### 素材来源（按优先级，不要跳级）

1. **用户提供的真实产品图** —— 永远优先。真实渲染图无法被合成替代。
   用 [`../starter-components/image-slot.js`](../starter-components/image-slot.js) 的 `<image-slot>` 组件把槽位直接交给用户：他把图片文件拖进槽位即可填充，填充结果经 sidecar 持久化，刷新、分享链接、导出 PPTX 都保留。**这是拿到真实产品图最省事的路径** —— 先摆好正确比例的槽位，让用户往里丢图，比自己去找图强。
   （`<image-slot>` 的 `shape` / `radius` / `mask` / `fit` 属性控制槽位形状；宿主运行时之外它是只读的。）
2. **生成** —— 仅用于氛围图、纹理、背景意象，且环境确有图像后端时。按 [`../craft/sources/generate-images.md`](../craft/sources/generate-images.md) 检测并调用。
3. **占位** —— 同上用 `<image-slot>`，但留空不填。

> **占位优于糟糕的合成。** 这条立场与 `hi-fi-design` 一致：一张干净的占位块，比一张勉强生成的假产品图更接近可交付状态。AI 合成的人造产品图会立刻破坏这套语言的可信度 —— 它是奢侈品语境，破绽在这里代价极高。**不要用生成图冒充产品渲染图。**

### 硬性规则

- 主视觉**通版**，主页 21:9 或更高，环境页与商店 16:9。**不切圆角。**
- 产品渲染图用**带透明的 PNG/WebP**，搁在表面瓦片上，并承接全系统那唯一一处投影 `rgba(0,0,0,0.22) 3px 5px 30px`。产品图是整个系统里唯一该有阴影的东西。
- 配件栅格 **1:1 方裁**，`lg`（18px）圆角，浅中性底，产品居中留 20–40px 内边距。
- 影像背景色应与所在瓦片同族（拍摄时用的就是那块台面），让产品"落"在瓦片上而不是贴上去。
- **文字压在摄影上时必须加 `--scrim-top` / `--scrim-bottom`。** 不加的话，白字能不能读完全取决于镜头碰巧拍到了多亮的像素 —— 换一张图就崩。scrim 只在文字那一侧渐隐，不要糊满整图。
- **主视觉给足高度。** D 编排的通版影像可以用视口高度（`min(88vh, 900px)` 一类），不要为了"上面还有内容"把它压成一条缝。2015 年的主视觉是 21:9 的扁条；现在它是页面的第一个整屏。

### 响应式影像

- 全部走响应式 `srcset` + `sizes`，按断点提供匹配裁切。
- **移动端可切换 art direction**，不只是缩放 —— 环境页的远景在移动端裁成更高的比例，重新构图主体。
- 产品渲染图跨断点保持 1:1 或 4:3，只缩放不裁切。
- 懒加载为默认；**首屏主视觉 eager 加载**（否则最大的那张图会最晚到）。

## 组件

### 导航

**全局导航** —— 常驻超细黑条。`--surface-black` 底，高 44px，12px/400/-0.12px 文字。链接安静，间距约 20px。右侧簇：搜索、购物袋图标。约 834px 以下折叠为汉堡，Apple logo 居中。

**子导航（磨砂）** —— 粘在全局导航下方。米白 80% + 背景模糊，高 52px。左侧类目名用 `tagline`（21px/600），右侧行内链接用 `button-utility`（14px），末端常驻主 CTA。

### 按钮

| 组件 | 规格 |
|---|---|
| **主按钮** | `#0066cc` 底，白字 `body`（17px/400），**全药丸圆角**，内边距 11×22。按下 `transform: scale(0.95)`（全系统微交互），焦点 2px `#0071e3` 外框。**全药丸圆角本身就是品牌动作信号** |
| **次级药丸** | 两个蓝 CTA 并排时用。透明底，`#0066cc` 字，1px 同色边框，药丸，11×22。读作"幽灵药丸" |
| **深色工具按钮** | 全局导航动作（登录、购物袋）。`#1d1d1f` 底，白字 14px/400/-0.224px，`sm`（8px）圆角，8×15 |
| **珍珠白胶囊** | 产品卡次级按钮。`#fafafc` 底，`#333` 字 14px，3px `#f0f0f0` 边框（起柔和描边作用而非可见线条），`md`（11px）圆角，8×14 |
| **商店主视觉 CTA** | Action Blue + 白字，18px/**300**（罕见字重），内边距 14×28，商店落地页少量使用 |
| **圆形图标按钮** | 浮在照片上。44×44，`rgba(210,210,215,0.64)` 底，图标 `#1d1d1f`，全圆。用于轮播控件、关闭按钮、图内控件 |

文字链接：`#0066cc`（浅面）或 `#2997ff`（暗面）。按场景决定是否加下划线。

### 卡片与容器

### 瓦片编排 —— 四种，混着用

**这是本模式最容易做旧的地方。** 如果每个瓦片都长成"居中标题 → 一行副标 → 两枚药丸 → 居中大图"，
字号调多大都救不回来 —— 那是 2015 年唯一的模板，而现在它只是四种里最少用的一种。

| 编排 | 长什么样 | 什么时候用 |
|---|---|---|
| **A 宣言瓦片** | 通版底色，居中对齐，标题 + 一行副标 + 最多两枚 CTA，图在下方或没有 | 一页**最多一次**，用在开场 |
| **B 分栏瓦片** | 左右各半：一侧文字（**左对齐**）、一侧影像。相邻瓦片左右互换 | 讲清一个功能的主力编排 |
| **C Bento 网格** | 2×2 / 3×2 卡片网格。卡片 `xl`（28px）圆角、白或米白底、彼此留 20–24px 间隙 | 一次讲一组特性 |
| **D 通版影像瓦片** | 摄影铺满，文字压在图上，配 `--scrim-*` | 情绪的落点，一页 1–2 次 |

**文字纪律：一个瓦片内的正文不超过一句**（约 40 字）。说不完就下沉到"了解更多"或规格区。
现代 apple.com 的产品瓦片几乎不承载段落 —— 那是 2015 年的做法。

**对齐：A 与 D 居中，B 与 C 左对齐。** 全页一律居中是最典型的做旧信号。

**底色节奏**：在白 / 米白 `#f5f5f7` / 深色 `#1d1d1f` 之间轮换，**颜色变化本身就是分隔线**，瓦片之间 0 间隔。
不要用"差一档的深灰"去分隔相邻暗瓦片，那读起来像渲染误差而不是节奏；深色区内部要抬起卡片才用 `--surface-tile-3`。

**四种瓦片的公共属性** —— 通版、`0` 圆角（圆角只属于浮在页面上的一张卡）、纵向内边距 96px（宣言与通版影像瓦片 120px）、标题上方至少 64px 空气。深色瓦片上的行内链接改用 `#2997ff`，主按钮的 Action Blue 在暗面上依然可用。

**商店工具卡** —— 1px `#e0e0e0` 边框，`lg`（18px）圆角，24px 内边距。上方产品图（1:1 裁切 + 8px 内层圆角），下方产品名 `body-strong`（17px/600）、价格 `body`（17px/400）、文字链接。**默认无阴影**，产品渲染图自带系统产品阴影。

**配置器选项 chip** —— 药丸形可点单元。白底，`caption` 字，药丸圆角，12×16。含小缩略图 + 标签 + 价格增量。每行 4–5 个。选中态边框升级为 2px `#0071e3`。

**悬浮吸底条** —— 米白 80% + 背景模糊，高 64px，内边距 12×32。左侧实时总价 `body`，右侧主按钮。

### 表单

**搜索框** —— 白底 17px 字，1px `rgba(0,0,0,0.08)` 边框，**全药丸圆角**（搜索也是药丸，与 CTA 语法一致），12×20，高 44px，前置 14px 搜索图标。

## 响应式

### 断点

| 名称 | 宽度 | 关键变化 |
|---|---|---|
| 小手机 | ≤ 419px | 单列瓦片；子导航只剩类目名 + 主 CTA；B/C 编排全部塌成单列 |
| 手机 | 420–640px | 单列堆叠；产品渲染图缩到瓦片宽 80% |
| 大手机 | 641–735px | 瓦片内边距收紧（64px 纵向 vs 96px） |
| 平板竖 | 736–833px | 全局导航折叠为汉堡；子导航隐藏类目 chip，保留主 CTA |
| 平板横 | 834–1023px | 全局导航恢复展开；bento 3 列变 2 列 |
| 小桌面 | 1024–1068px | B 编排开始并排（此前一律上下堆叠） |
| 桌面 | 1069–1440px | 完整布局；4–5 列商店栅格；内容上限 1440px |
| 宽桌面 | ≥ 1441px | 内容锁 1440px，多余宽度由边距吸收 |

**结构性断点：1440（内容锁）、1068、833、734、640、480。**

### 触控目标

最小 44×44px。主按钮约 44×100px（全药丸圆角让可见命中区比标签更大）。圆形图标按钮正好 44×44。**全局导航工具链接更小（约 32×80）** —— 它们是桌面精密动作，833px 以下由汉堡替代。

### 折叠策略

- 全局导航：桌面完整链接行 → 834px 及以下折叠为 logo + 汉堡 + 购物袋
- 子导航：类目名 + 行内链接 + 主 CTA → 移动端只剩类目名 + 主 CTA
- B 分栏瓦片：**1023px 及以下一律上下堆叠**，文字在上影像在下；并排是宽屏特权
- bento 网格：3 列 → 2 列（1023）→ 1 列（640）
- 工具栅格：5 列 → 4 列（1440）→ 3 列（1068）→ 2 列（834）→ 1 列（640）
- **主视觉字号不在此列** —— `--text-hero-display` 是 `clamp(40px, 6.5vw, 96px)`，
  由 CSS 自己接管。结构断点只管布局，不再兼职降字号。

## Do / Don't

**Do**
- 每个交互元素都用 `#0066cc`，且只用它。**单一强调色不可协商。**
- 显示尺寸给足。瓦片标题 56px、主视觉流式到 96px —— 不够大就退回 2015 年了。
- 标题用负字距、显示级行高压到 1.04–1.15，拿到"Apple 紧"的韵律。
- 字距用 `em`，让收紧量随字号缩放。
- 正文跑 17px —— 不是 16px。正文行高 1.5。
- 四种瓦片编排混着用，**每个瓦片内正文不超过一句**。
- 底色在白 / 米白 / `#1d1d1f` 之间轮换。**颜色变化就是分隔线。**
- `pill` 只留给主蓝色 CTA 和任何应该读作"动作"的元素。
- 产品阴影只给搁在表面上的产品渲染图。
- `transform: scale(0.95)` 作为每个按钮的按下态。
- 文字压在摄影上时加 `--scrim-*`，否则对比度靠运气。

**Don't**
- 不要引入第二个强调色。
- 不要给卡片、按钮、文字加阴影。
- 不要用渐变做装饰性背景（文字压图时的 scrim 不在此列，那是功能件）。
- 正文不要用 500 字重。
- 不要给通版瓦片加圆角。
- 正文行高不要低于 1.5。
- **不要在浅色面上用 `#2997ff`** —— 它是暗瓦片专属变体。
- **不要连着做两个"居中堆叠"瓦片。** 那是 2015 年唯一的模板，现在只是四种之一。
- **不要用"差一档的深灰"（`#272729` / `#2a2a2c`）分隔相邻暗瓦片。** 那读起来像渲染误差。深色瓦片用 `#1d1d1f`，要更重就用 `#000`，对比要拉开。
- **不要在瓦片里写段落。** 超过一句就下沉到"了解更多"或规格区。
- **不要全页一律居中。** B 与 C 编排左对齐，只有 A 与 D 居中。

## CJK 排版

> 与 `apple/design-language.md` 冲突时以后者为准。


界面同时出现中文（或日文、韩文）与拉丁文时：

- **用拉丁优先的系统 CJK 字体栈**，让每种文字都拿到正确的字形：
  `font-family: -apple-system, "SF Pro Text", "PingFang SC", "Noto Sans SC", sans-serif;`
  （`web` mode 下正文/UI 用 `--font-text`、大字用 `--font-display`，都已在 `apple/web-tokens.css` 里定义好，直接引用即可；上例是无 token 可用时的兜底形态。）
- **中文正文行高要比拉丁文更大**（阅读场景约 **1.7–1.8**）—— 汉字密度高，需要更多纵向空间。
- **给内容打 `lang="zh"` / `lang="en"`**，浏览器才能选对字体与断行规则。
- **多数"阅读型衬线"网页字体不覆盖 CJK。** 若提供衬线阅读模式，必须给拉丁衬线配一个中文衬线兜底（如 `"Newsreader", "Songti SC", "Noto Serif SC", serif`）—— 否则中文会静默回退到无衬线，衬线开关在中文文本上看起来就是坏的。
